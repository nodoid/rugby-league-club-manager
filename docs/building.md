# Building, signing and deploying

## Prerequisites

- **.NET 10 SDK** (`dotnet --version` → 10.x).
- **Workloads**: `dotnet workload install android ios` (macOS; iOS builds need Xcode).
- **Xcode** with the iOS 27 SDK and command-line tools selected (`xcode-select -p`).
- **Python 3 with Pillow** only if you want to regenerate the art (`pip install pillow`).
- The MonoGame content builder tool is restored as a NuGet package; no separate install is needed.

The solution is `RugbyLeague.slnx`:

```bash
dotnet build RugbyLeague.slnx
dotnet test tests/RugbyLeague.Core.Tests
```

## Desktop (development)

```bash
dotnet build src/RugbyLeague.DesktopGL
dotnet run --project src/RugbyLeague.DesktopGL
```

The window is resizable; **F12** writes a screenshot next to the executable. The desktop build is the
fastest way to check UI changes, and it uses the same content pipeline as the phone builds.

## Android

`src/RugbyLeague.Android` targets `net10.0-android` with `SupportedOSPlatformVersion` 32, so it
installs on Android 12 and later. The manifest deliberately has no `<uses-sdk>` element — the
workload generates it from the project properties, and adding one causes build error XA1036.

```bash
# Debug build, installed on a connected device or emulator
dotnet build src/RugbyLeague.Android -t:Run

# Release APK (debug-key signed unless you provide a keystore)
dotnet build src/RugbyLeague.Android -c Release
# -> src/RugbyLeague.Android/bin/Release/net10.0-android/uk.co.allthejohnsons.rugbyleaguegame-Signed.apk

adb install -r src/RugbyLeague.Android/bin/Release/net10.0-android/uk.co.allthejohnsons.rugbyleaguegame-Signed.apk
adb shell am start -n uk.co.allthejohnsons.rugbyleaguegame/crc64….MainActivity
```

For a store build, create a keystore and sign with it:

```bash
keytool -genkeypair -v -keystore rugby.keystore -alias rugby -keyalg RSA -keysize 2048 -validity 10000
dotnet publish src/RugbyLeague.Android -c Release \
  -p:AndroidKeyStore=true \
  -p:AndroidSigningKeyStore=rugby.keystore \
  -p:AndroidSigningKeyAlias=rugby \
  -p:AndroidSigningKeyPass=env:RUGBY_KEY_PASS \
  -p:AndroidSigningStorePass=env:RUGBY_STORE_PASS
```

Launcher icons (including adaptive icons for API 26+) and splash screens live in
`src/RugbyLeague.Android/Resources/` and are generated by `tools/generate_assets.py`.

## iOS

The iOS head targets `net10.0-ios` with `SupportedOSPlatformVersion` 18.0 and bundle id
`uk.co.allthejohnsons.rugbyleaguegame`.

### Signing setup

Nothing signing-related is committed: team, certificate and profile details are personal to whoever
is building. Put them in an untracked `LocalSigning.props` in the repository root (the project
imports it when it exists):

```bash
cp LocalSigning.props.example LocalSigning.props
```

```xml
<Project>
  <PropertyGroup>
    <CodesignKey>Apple Development: Your Name (XXXXXXXXXX)</CodesignKey>
    <CodesignProvision>your-development-profile</CodesignProvision>
  </PropertyGroup>
</Project>
```

`LocalSigning.props`, `*.mobileprovision`, `*.p12` and `*.keystore` are all in `.gitignore`.

Install the profile under `~/Library/MobileDevice/Provisioning Profiles/` and confirm the identity
is present with `security find-identity -v -p codesigning`. For a release or TestFlight build, point
the same two properties at the distribution identity and profile.

### Device build

Xcode 27 ships a newer SDK than the installed iOS workload advertises, so the version check must be
disabled explicitly:

```bash
dotnet build src/RugbyLeague.iOS -c Release \
  -p:RuntimeIdentifier=ios-arm64 \
  -p:ValidateXcodeVersion=false
```

The app bundle is produced at
`src/RugbyLeague.iOS/bin/Release/net10.0-ios/ios-arm64/RugbyLeague.iOS.app`. Use `-t:Rebuild` after
changing `Info.plist` or any file that is copied rather than compiled — incremental builds do not
always refresh the bundle's plist.

### Deploy to a physically connected iPhone

Find the device UDID with `xcrun devicectl list devices`, then:

```bash
DEVICE=<your-device-udid>

xcrun devicectl device install app \
  --device $DEVICE \
  src/RugbyLeague.iOS/bin/Release/net10.0-ios/ios-arm64/RugbyLeague.iOS.app

xcrun devicectl device process launch \
  --device $DEVICE \
  --console uk.co.allthejohnsons.rugbyleaguegame
```

Useful follow-ups:

```bash
# Screenshot (PNG, native device resolution)
xcrun devicectl device capture screenshot --device $DEVICE --destination /tmp/ios.png

# Confirm the process is alive
xcrun devicectl device info processes --device $DEVICE | grep -i rugby

# Pull crash reports
mkdir -p /tmp/crash
xcrun devicectl device copy from --device $DEVICE \
  --domain-type systemCrashLogs --source . --destination /tmp/crash
```

`devicectl` works only with a paired, unlocked device that has trusted the Mac; the first launch
may need the developer certificate trusted under **Settings → General → VPN & Device Management**.

### Scene lifecycle requirement (iOS 27)

The build originally crashed at launch with `EXC_BREAKPOINT` inside
`___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption_block_invoke`. iOS 27 kills apps
that have not adopted UIScene. MonoGame 3.8 creates its `UIWindow` itself and has no scene support,
so the head now supplies it:

- `Info.plist` declares `UIApplicationSceneManifest` with `UIApplicationSupportsMultipleScenes =
  false` and one `UIWindowSceneSessionRoleApplication` configuration named *Default Configuration*
  whose delegate class is `SceneDelegate`.
- `Program.cs` implements `[Register("SceneDelegate")] SceneDelegate : UIWindowSceneDelegate` and,
  in `WillConnect`, creates the game, assigns `game.Window.WindowScene = scene`, calls `Run()` and
  then `MakeKeyAndVisible()`.

If you replace MonoGame with a version that handles scenes itself, remove both pieces together.

### Troubleshooting

| Symptom | Fix |
| --- | --- |
| `error MT0091` / unsupported Xcode version | add `-p:ValidateXcodeVersion=false` |
| `No code signing identity found` | fill in `LocalSigning.props`, install the profile, re-run `security find-identity` |
| App installs but immediately exits | pull the crash log; check `Info.plist`/scene delegate first |
| Launch on the wrong device | always pass `--device <UDID>`; never use `simctl` |
| Incremental build ignores plist changes | `dotnet build … -t:Rebuild` |
| Android `XA1036: <uses-sdk> in the manifest` | remove `<uses-sdk>`; set `SupportedOSPlatformVersion` instead |

## Store captures

Screenshots and the App Store preview are recorded on simulators that nobody is tapping, so the
game can drive itself: set `RL_DEMO=1` (or pass `--demo`) and it runs a scripted tour of the menu,
dashboard, squad, competitions, matchday and a 3D match, then exits after about 26 seconds.

```bash
SIM=<$SIMULATOR_UDID>
SIMCTL_CHILD_RL_DEMO=1 xcrun simctl launch $SIM uk.co.allthejohnsons.rugbyleaguegame
xcrun simctl io $SIM recordVideo --codec=h264 preview.mp4   # stop with Ctrl-C
```

The tour lives in `src/RugbyLeague.Game/Demo/DemoTour.cs`; adjust the timings there if the screens
change. Store artwork and copy are in [`store/`](../store).

## Assets

All art is generated from `tools/generate_assets.py`. Rerun it after changing colours or dimensions:

```bash
python3 tools/generate_assets.py
```

It writes in-game textures to `src/RugbyLeague.Game/Content/Textures`, Android icons/splash to
`src/RugbyLeague.Android/Resources`, the iOS asset catalog to `src/RugbyLeague.iOS/Assets.xcassets`
and reference art to `docs/images`. See [assets.md](assets.md).
